# Automatic metadata update from identical covers — 2026-11-12

User authorized replacing playback/manual approval with automatic writes for identical cover files. On the currently open 25-row batch page, the browser scans the complete video library and then applies eligible rows one at a time. Only nonempty title/description from the staged file are written; similarity scores below an exact SHA-256 match do not qualify.

The API keeps a bounded, user-bound scan session (64 sessions, one-hour expiry), checks sequential cursors, and requires a completed scan with no unreadable candidate covers and matching scanned/total counts. A row must have one exact video candidate, and that candidate cannot be shared by another row on the current page. Multiple matches, failed/incomplete scans, invalid rows and missing source images remain manual. Duplicate sources on other pages are not globally resolved by this per-page scan.

Before writing, the API reloads source and selected poster bytes with fresh cache keys and verifies SHA-256 again. The video version must still match at preview; the existing apply transaction rechecks video/source state, writes the text and before/after audit, and supports rollback. Audit records include exact_cover_sha256, hash and timestamp, without falsely marking video playback as reviewed. Replayed applied rows do not write again. All routes retain administrator/session/CSRF controls. Client-submitted target IDs or exact-match booleans are not accepted as proof.

No schema migration. Video IDs/publicIds/owners/storage keys/R2 media/iframe/access permissions are unchanged. Existing imports stay pending until an administrator opens their batch page. Stop/page navigation aborts subsequent requests; already committed rows remain saved and can be rolled back through history. A process restart or requests sent to another API instance lose the in-memory scan session and require a fresh scan (no fallback bypass).

Validation: API and admin TypeScript checks passed. API tests: 45 passed (9 new automatic-match cases plus existing image/parser/reference tests). UI hook tests: 3 passed, proving automatic request without playback/click, no request for ineligible rows, and honest display of failure. Production deployment and playback were not tested.
