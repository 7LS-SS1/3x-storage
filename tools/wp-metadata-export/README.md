# RetroTube Metadata Backup Export 1.1.3

ปลั๊กอินชั่วคราวสำหรับสำรองและตรวจสอบ metadata ของ RetroTube ที่ใช้ Video embed code โดยตรง ใช้งานได้โดยไม่ต้องมี 7M/AURUM Video Core และไม่เชื่อมต่อ API หรือฐานข้อมูลของ 3x-storage

## วิธีใช้

1. ติดตั้ง `wp-metadata-export-1.1.3.zip` ผ่าน Plugins → Add New → Upload Plugin แล้วเปิดใช้งาน
2. ใช้บัญชีผู้ดูแลที่มี `manage_options` เปิด Tools → Metadata Backup Export
3. เลือก `post` สำหรับบทความวิดีโอ RetroTube เลือกสถานะ เลือกวันที่เผยแพร่หรือวันที่แก้ไข ช่วงวันที่อิง timezone ของ WordPress ที่แสดงบนหน้าจอ และรวมวันสุดท้าย
4. เลือก **บทความทั้งหมดตามตัวกรอง** แล้วกด **ตรวจสอบทั้งหมด** ระบบอ่านครั้งละ 50 รายการต่อเนื่องจนจบ ตรวจยอดสำเร็จ/ล้มเหลว จากนั้นตรวจ content, embed, taxonomy, warnings และ excluded_meta_keys ในไฟล์ที่บันทึก
5. กด **ยืนยันและบันทึก JSON + CSV** แล้วเลือกโฟลเดอร์ส่วนตัวบนเครื่องด้วย Chrome/Edge ผ่าน HTTPS หรือ localhost ปลั๊กอินจะสร้าง JSON, CSV และ `-report.json` ชื่อใหม่ ไม่ทับไฟล์เดิม
6. ตรวจยอดสำเร็จ/ข้าม/ล้มเหลว และ `summary.count_matches` ต้องเป็น true ตรวจเหตุผลใน report และ warnings ทุกครั้ง รายการที่ล้มเหลวจะไม่รวมใน records
7. หากต้องการทั้งหมด เลือก **บทความทั้งหมดตามตัวกรอง** และ **ทุกสถานะ** เว้นช่วงวันที่ว่าง ไม่ต้องล้าง Post ID ที่กรอกค้างไว้ ระบบจะไม่ใช้ ID ในโหมดทั้งหมด ตรวจสอบทั้งหมดและยืนยันอีกครั้ง การเปลี่ยนตัวกรองจะทำให้ต้องตรวจใหม่
8. เมื่อสำรองครบ ปิดใช้งานและลบปลั๊กอินได้ ไม่มีตาราง options cron หรือไฟล์ export ฝั่งเซิร์ฟเวอร์ที่ต้องล้าง

ไม่แสดงหรือเล่น iframe; ตัวอย่างเป็นข้อความที่ escape แล้ว ไม่ดาวน์โหลดไฟล์รูปหรือวิดีโอ หน้า Export ไม่เขียนข้อมูลต้นทาง ส่วนหน้า Import ที่เพิ่มในรุ่น 1.1.2 แก้เฉพาะ embed หลังผู้ดูแลยืนยัน ไม่แก้ข้อมูลใน 3x-storage

## ความหมายของไฟล์

- JSON เป็นข้อมูลหลัก UTF-8: เก็บ HTML/shortcode ต้นฉบับ, meta หลายค่าและค่า array/object, `stored_raw` สำหรับค่าที่จัดเก็บจริง, term ทุก taxonomy รวมที่ไม่ได้ register ในปัจจุบัน
- `video_embed_code_raw` เป็น array ของ `{source_field, value_index, value}` เพื่อไม่ทำค่าซ้ำต่อ key หาย เช่น embed สองค่า
- `iframe_sources` เก็บ `src_raw`, `src_decoded`, hostname และ `parsed_embed_id` แยกกัน ID มีสถานะ `parsed_only_not_verified_video_id` เสมอ ไม่มีการจับคู่กับ 3x-storage
- CSV เป็นสรุปหนึ่งบรรทัดต่อโพสต์ หลาย iframe อยู่ในเซลล์เดียวคั่นด้วย newline พร้อม quote ตาม CSV มี BOM สำหรับ Excel และเติม `'` หน้าเซลล์ที่เสี่ยงเป็นสูตร JSON ไม่ถูกแก้ตาม CSV
- report เก็บรายการ Post ID ที่ข้าม/ล้มเหลวพร้อมเหตุผลและยอดรวม เก็บ report คู่กับ JSON และ CSV
- รูปที่ไม่พบเป็น null/array ว่าง `filename` เป็น basename ที่อนุมานจาก `_wp_attached_file` ส่วน `original_filename` จะมีเฉพาะเมื่อ WordPress บันทึก `original_image` ไว้จริง URL จาก WordPress API ไม่ได้ตรวจผ่านเครือข่าย

## ข้อจำกัดที่ต้องตรวจ

- ติดตั้งชั่วคราวเพื่อ export metadata เท่านั้น ไม่ใช่การสำรองฐานข้อมูลหรือไฟล์ media ทั้งระบบ ไม่รวม options, user metadata หรือรหัสผ่านบทความ
- Export เฉพาะ custom fields ที่มีหลักฐานและอยู่ใน mapping ของ RetroTube; key อื่นถูกระบุชื่อและเหตุผลใน `excluded_meta_keys` ไม่ทิ้งเงียบ ๆ ต้องตรวจรายการนี้ก่อนถือว่าข้อมูลที่ต้องการครบ หากไซต์มี custom fields เพิ่ม ต้องตรวจโค้ดต้นทางและเพิ่ม mapping ก่อน export ใหม่
- ตรวจชื่อ key, nested key และรูปแบบค่าที่เป็น credentials; ฟิลด์ที่มี signed URL/token จะถูกตัดพร้อมเหตุผล โดยไม่แก้ URL หากอยู่ใน content/title/ข้อมูลดิบที่ต้องคงเดิม จะปฏิเสธทั้งรายการแทนการแก้ต้นฉบับ การตรวจรูปแบบไม่สามารถยืนยันข้อความลับที่ไม่มีชื่อ/รูปแบบบ่งชี้ได้ ห้ามนำไฟล์สำรองไปเผยแพร่สาธารณะ
- PHP object ไม่ถูก instantiate ระหว่าง unserialize เก็บค่าที่ decode ได้และ serialized bytes เดิม ไม่ได้รัน shortcode หรือ WordPress content filters
- อ่านครั้งละ 50 โพสต์ เรียง ID แบบ keyset มีขอบเขต max ID ตั้งแต่เริ่ม แต่ละ batch ใช้ transaction READ ONLY / REPEATABLE READ และ ROLLBACK เสมอ การ export ทั้งชุดไม่ใช่ snapshot เดียวข้าม request จึงควรงดแก้บทความระหว่าง export และตรวจยอดเมื่อเสร็จ
- หน่วยความจำขึ้นกับขนาดหนึ่ง batch และโพสต์แต่ละรายการ ไม่ใช่ทุกโพสต์ในเว็บ; โพสต์/meta ที่ใหญ่มากอาจชน memory/time limit ของ PHP ได้ ไม่มี resume หลัง reload/nonce หมดอายุ ให้เริ่ม export ใหม่หรือแบ่งช่วงวันที่
- ต้องใช้ browser ที่มี File System Access; Firefox/Safari และ HTTP ที่ไม่ใช่ localhost ไม่รองรับ flow นี้ กดหยุด/เขียนดิสก์ล้มเหลวจะ abort ไฟล์ที่ยังไม่ commit อาจเหลือชื่อไฟล์ว่าง ถ้าไฟล์แรก commit แล้วแต่ไฟล์ถัดไปล้มเหลว หน้าจอจะแจ้งว่าชุดไฟล์ยังไม่ครบ
- การหา iframe ใช้การอ่าน tag/attribute จากข้อความ ไม่รัน DOM หรือ shortcode iframe ที่ถูกสร้างด้วย JavaScript/shortcode ตอนแสดงผลจะไม่ถูกสร้างเพิ่ม ส่วนต้นฉบับยังอยู่ครบ

รายละเอียดหลักฐาน mapping และผลทดสอบอยู่ที่ `docs/WORDPRESS_METADATA_EXPORT.md` ใน source project


## นำเข้า embed จาก CSV ของ 3x-storage (1.1.2)

1. Export CSV จากคลังวิดีโอ 3x-storage แล้วเปิด Tools → 3x-storage Embed Import
2. เลือก post type และไฟล์ CSV UTF-8 ที่มีคอลัมน์ `title,หมวดหมู่,videos url,url images` ตามแอปจริง ขนาดไม่เกิน 10 MiB / 2,000 รายการ (ยังขึ้นกับ upload_max_filesize/post_max_size ของ PHP)
3. กดตรวจไฟล์ ระบบจับคู่ title ตรงทุกตัวอักษร ไม่ตัดช่องว่าง ไม่ใช้ชื่อคล้ายกัน ย้อนเฉพาะ apostrophe ที่แอปเติมป้องกันสูตร CSV ชื่อซ้ำในไฟล์หรือ WordPress จะถูกบล็อก
4. ตรวจ Post ID สถานะ และ embed เดิม–ใหม่ แล้วกดยืนยันทีละรายการ เริ่ม 1–2 รายการก่อน ช่องหมวดหมู่และรูปภาพจะไม่ถูกนำมาแก้ไข
5. เก็บค่าเดิม–ใหม่ ผู้ดำเนินการ เวลา UTC และ batch ID ใน `_wpmb_embed_audit` ของบทความ กดปุ่มย้อนคืนหรือเปิดหน้าใหม่เพื่อดูประวัติ 50 รายการล่าสุด หาก embed ถูกแก้ภายหลังจะไม่ย้อนทับโดยอัตโนมัติ

แก้เฉพาะ meta key `embed` ที่ตรวจจาก RetroTube ไม่แก้ post_content/ชื่อเรื่อง/รูป/3x-storage รองรับเฉพาะ iframe รูปแบบที่แอป export ไม่รัน iframe หรือ fetch URL ระหว่างตรวจ ตัวอย่าง HTML แสดงเป็นข้อความเสมอ แต่หลังอนุมัติ RetroTube จะใช้ iframe ใหม่นี้ในการเล่นจริง จึงต้องตรวจโดเมนและปลายทางก่อนยืนยัน

ใช้ transaction ต่อรายการสำหรับ embed และ audit พร้อมตรวจค่าเดิมก่อนเขียน ต้องเป็นตาราง InnoDB ไม่ต้อง migrate schema หากเครือข่ายหลุดหลังบันทึกให้ตรวจประวัติหรือ preview ใหม่ การนำเข้าซ้ำไม่เพิ่มค่า embed ซ้ำ ประวัติ audit จะยังอยู่หลังถอนปลั๊กอินเพื่อไม่ลบข้อมูลย้อนคืน

ขอบเขต “ทั้งหมด” ของ Export คือทุกบทความของ post type และตัวกรองที่เลือก เลือกทุกสถานะและเว้นวันที่ว่างเพื่อรวมร่าง/ส่วนตัว/ถังขยะด้วย ไม่มีเพดานจำนวนโพสต์ของ Export แต่รายการที่มีข้อมูลรับรองหรืออ่านไม่ได้ยังถูกแยกใน report ไม่ใช่สำรองทุกตารางหรือทุก secret

รุ่น 1.1.2: ตรวจครบทุก batch ก่อนเปิดปุ่มบันทึก แสดงข้อมูลทุก record เป็นข้อความ หากหยุด/เครือข่ายผิดพลาด/ยอดไม่ตรง ต้องตรวจใหม่ หน้าจอแสดงเฉพาะยอดสรุป ไม่สะสม JSON ของรายการทั้งหมด; PHP ยังอ่านทีละ 50 รายการ การดาวน์โหลดอ่านข้อมูลอีกครั้ง ไม่ใช่ snapshot เดียวกับการตรวจ จึงควรงดแก้ต้นทางระหว่างทำงาน

รุ่น 1.1.2 นำกล่องแสดง JSON ทั้งหมดออกเพื่อลดการใช้หน่วยความจำและการค้างของ browser โดยยังตรวจครบทุก batch และส่งออกข้อมูลเต็มเหมือนเดิม ไฟล์สำหรับนำเข้า 3x-storage ต้องไม่เกิน 500 รายการ / 10 MiB ต่อไฟล์; CSV สรุปไม่มีคำอธิบายครบเท่า JSON


## อนุมัติ import ทั้งหมด (1.1.3)

หลังเลือก CSV จาก 3x-storage แล้วกด **ตรวจไฟล์และแสดงรายการ** ให้กด **อนุมัติทั้งหมด / ยืนยันแก้ไขทั้งหมด** และยืนยันจำนวนครั้งเดียว ระบบส่งคำขอเรียงทีละรายการจนจบ เฉพาะรายการ ready ที่ยังไม่บันทึก ไม่รวมชื่อซ้ำ หาไม่พบ ค่าเดิมตรงกัน หรือรายการผิดเงื่อนไข

แต่ละรายการยังตรวจ nonce/capability/token/ค่าเดิม และใช้ transaction พร้อม audit ตามเดิม ข้อผิดพลาดของรายการหนึ่งไม่ย้อนรายการที่บันทึกสำเร็จก่อนหน้าและไม่หยุดรายการถัดไป หน้าจอสรุปรอบันทึก บันทึกแล้ว ข้าม ค่าเดิมตรงกัน ผิดพลาด/ยังยืนยันไม่ได้ และย้อนคืน ปุ่มรายรายการยังใช้ได้

กด **หยุดหลังรายการปัจจุบัน** เพื่อหยุดคิว แล้วกดอนุมัติทั้งหมดอีกครั้งเพื่อทำเฉพาะรายการที่เหลือ รายการที่ล้มเหลวหรือเครือข่ายขัดข้องไม่ถูกลองซ้ำอัตโนมัติ ให้ตรวจประวัติและตรวจไฟล์ใหม่ การเปลี่ยนไฟล์หรือ post type ทำให้ผลตรวจเดิมใช้อนุมัติไม่ได้ ต้องตรวจใหม่ เปิดหน้าไว้ระหว่างทำงาน; ไม่ใช่งาน background หลังปิด browser รายการที่บันทึกแล้วใช้ปุ่มย้อนคืนหรือประวัติได้


## รุ่น 1.1.4: จับคู่ด้วย old_embed
CSV จาก “Export รายการที่แก้ไขแล้ว” มีคอลัมน์ที่ห้า `old_embed` ซึ่งมาจากค่า `embed` ในข้อมูล WordPress ต้นฉบับของ batch เท่านั้น ไม่สร้างจาก URL ใหม่ หากไม่พบหลักฐานจะแสดงค่าว่างและปลั๊กอินบล็อกรายการนั้น

ปลั๊กอินเปรียบเทียบ URL ใน iframe src หลัง decode HTML entities แบบตรงกันทั้ง URL (รวม query/fragment) ไม่สนชื่อเรื่องหรือรูปแบบ HTML พบหลายบทความใน post type ที่เลือกจะสร้างรายการยืนยันให้ทุกบทความ ใช้ปุ่มอนุมัติทั้งหมดได้ ค่าเดิม/ใหม่ escape เป็นข้อความ ไม่เปิด iframe และไม่เรียก URL ภายนอก CSV ซ้ำที่ old/new embed เดียวกันจะรวมเป็นชุดเดียว แต่ถ้า old embed เดียวชี้ไปคนละ new embed จะบล็อกความขัดแย้ง

ไฟล์เก่า 4 คอลัมน์ยังใช้ชื่อเรื่องตรงทุกตัวอักษรตามเดิม แต่ไฟล์ใหม่ที่ old_embed ว่าง/ไม่พบจะไม่ย้อนใช้ชื่อโดยอัตโนมัติ แต่ละบทความบันทึกและย้อนคืนแยกกันด้วย transaction/audit เดิม ไม่มี schema migration
